# 会议纪要阅读设计

当前实现和兼容规则见[会议纪要展示契约](../contracts/MINUTES-CONTRACT.md)。本页保留设计依据和读者验收目标。调研来源见 [MEETING-MINUTES-RESEARCH.md](MEETING-MINUTES-RESEARCH.md)。

## 问题

早期默认交付沿用证据报告，主题、决定和任务旁直接陈列引用及定位信息。证据报告适合逐条复核，常规纪要的正文则需要先交代决定、进展和执行安排。

## 默认成品

插件的普通报告请求默认交付简洁纪要和溯源附录，分析 JSON 供验证与渲染使用。正文依次呈现决定、进展、后续与待确认事项。CLI 和 MCP 的直接调用在未提供纪要编辑稿时仍默认输出证据报告。

| 部分 | 内容 | 取舍 |
|---|---|---|
| 标题与基本信息 | 可理解的会议主题；已知日期/参会者 | 不用哈希做标题；未知信息不编造，不把文件名日期视为已确认会议日期 |
| 一句话概要 | 最重要的进展、方向或卡点 | 直接写结果，不写“本次主要讨论了……”的空泛开场 |
| 已确认决定（若有） | 决定、适用范围、必要理由或条件 | 没有明确决议就省略，不用建议/计划凑数；重要否决或分歧不能省略 |
| 当前进展（若有） | 合并成少量工作事项，说明做到哪一步 | 已完成的汇报不重复列为待办；不能把本地测试等同生产验收 |
| 后续安排 | 动词开头的具体行动；已知负责人、期限、必要前提 | 通常 3—4 列。各事项负责人/期限均未知时，正文统一说明，不重复整表 TBD |
| 需确认或需协调 | 会影响实施的未决事项，说明缺什么决定/信息 | 未经授权不写成“领导必须批准”；整理建议与会上承诺分开 |
| 来源入口 | 链接到逐条依据和完整任务 | 主文不逐项堆原句，但可保留轻量编号；关键争议可就地放一条时间定位 |

正文目标是一屏到一页可扫读；中等复杂会议可先按约 500—800 中文字设计。这是本产品的起始设计预算，不是行业标准，也不是硬性截断规则。多议题会议可以更长，不能丢掉重要决定、条件、分歧或任务来凑字数。

## 表达规则

- 使用短句，先写结论，再写会改变执行的条件；同一事实尽量只出现一次。
- 按项目/事项归并，同类任务可在正文合并展示，但保留所有原任务 ID 到正文事项的映射，方便展开。
- 合并后的事项只是工作集合，不能冒充新的、可直接派发的原子任务。
- 只保留有内容的栏目；全中文标签；不显示机器 ID、置信度、校验日志。
- 正文中的“已完成”“已决定”“待执行”“建议”“待确认”含义必须清楚。不要为了语言简洁而抹掉条件或改强语气。
- 未知负责人和日期保留为未知。发布前由组织者确认；不擅自补部门、优先级、日历日期或交付物承诺。
- 能读懂的缩写只保留必要范围；术语有疑义放入需确认，不把语音乱码润色成自信的业务结论。
- 审批、重大风险、采购等正式记录仍应保留所需的背景、理由、异议、利益冲突和批准范围；简洁模板不能取代法定或组织要求。

## 简短示例（虚构）

不佳：`[proposed] 执行升级；confidence: high；Evidence: abc123 / seg-7 ...`。

较好：`升级安排：测试通过后再发布；发布时间待确认。` 引用与原句放在来源附录中。

不佳：`会上大家就退款能力进行了充分沟通，并表达了后续持续推进的意愿。`

较好：`退款功能：继续开发，完成时间待确认。`

## 实现分工

1. `minutes`、`actions` 与 `evidence` 使用同一份分析。切换阅读模式不改变事实状态。
2. Skill 指导宿主生成独立的 `minutes-contract@1.0` 编辑稿。运行时检查引用、条目 ID 和任务覆盖。纯汇报没有可引用条目时，正文直接使用分析议题，相关证据在附录保留。
3. 渲染器负责中文状态、栏目显示、表格与附录；语义压缩、分组和选重点由宿主模型负责，不能把确定性渲染误称为智能编辑。
4. 对尚未归并的数据先提供完整行动表。默认摘要不能只显示“前五项”而不说明其余任务位置。
5. 短稿必须能追到对应原任务/结论；无依据的建议不混入提取结果。长文展示重构不取消现有 Schema/证据校验。
6. 当前真实样稿仅存在 Git 忽略目录中，不进入仓库、公共样例或插件包。

## 验收标准

- 未参加会议的读者能迅速回答：目前进展、正式决定、下一步、负责人/日期、最大未决项。
- 所有原始行动都能在正文或明确链接的完整清单找到；无遗漏，无新增承诺。
- 条件性部署、否决/分歧、已完成与待办不被混淆；未知归属不被模型擅自补齐。
- 常规阅读不需要经过任何逐条引文、哈希或置信度；需要时仍能核验来源。
- 用读者实际找任务、找负责人、找条件的任务测试来判断改善，不用缩字比例代替可用性验证。
